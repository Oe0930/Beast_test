# ESP32 操作画面

## gyroTurnの異常時停止

`gyroTurn`環境では、`BNO055Controller::TryUpdateEuler()`でI2Cの読み取り成否とBNO055のNDOF動作状態を確認してから角度を使います。正常な0度は有効な測定値として扱い、通信失敗を0度とみなして走行を続けることはありません。既存の`Update()`は他のテストとの互換性のため残しています。

通信失敗、センサー状態異常、PID出力の非有限値、または旋回開始から10秒経過した場合は、モーターを停止して旋回を中止します。異常後は再起動するまで次の旋回を開始しません。制限時間は`src/gyroTurn.cpp`の`turnTimeoutMs`で変更できます。

I2Cの待ち時間は100msに設定し、旋回制限時間を読み取りの前後で確認します。応答待ち中はソフトウェアが停止条件を確認できないため、厳密な停止時刻を保証するものではありません。

`test/gyro_turn/test.cpp`では実際のセンサー取得・旋回処理を読み込み、I2C・時刻・モータードライバー・PIDを模擬して検証します。WindowsのVisual Studio開発者コマンドプロンプトでは、次のコマンドで実行できます（プロジェクトのルートで実行）。

```text
cl /nologo /utf-8 /EHsc /std:c++17 /Itest/gyro_turn/mocks /Ilib/_others /Ilib/BNO055Controller test/gyro_turn/test.cpp /Fe:.pio/tests/gyro-turn-tests.exe /Fo:.pio/tests/gyro-turn-tests.obj
.pio\tests\gyro-turn-tests.exe
```

出力先`.pio/tests`を事前に作成してください。このテストは実機へ接続せずに実行するため、実際の配線・モーターの停止確認は別途必要です。

## ラジコン操作ページ

`src/radiconGUI.cpp`に対応する画面は`data/index-radicon.html`です。ハンドル（-1〜1）、走行パワー、押している間だけ動く前進・後退ボタン、停止ボタンがあります。ハンドルが大きいと片輪が逆転する方式です。走行ボタンを離すとパワーを0へ戻し、画面のハンドル位置は保持します。停止ボタン・通信エラー時もハンドル位置を保持し、「中央へ」ボタンで中央へ戻します。

PCでHTMLを直接開くかlocalhostで開くとプレビューになり、ESP32への命令は送信しません。実機で使うときはPlatformIOの**radiconGUI**環境を選択して書き込みます（現在のデフォルト環境はBNO055_testです）。HTMLもファームウェアへ埋め込まれるので、ファイルシステムの別途書き込みは不要です。

接続先Wi-Fiは`lib/_others/settings.hpp`のSSID（現在Oe-GUItest）、パスワードは同ファイルのpass（現在12345678）です。Safariで`http://192.168.100.1/`を開きます。`/setting`では接続情報を表示します。

画面は`GET /steering?steering=-0.50`と`GET /power?power=-0.30`を使います。どちらも-1〜1の有限な小数のみ受け付け、不正値はHTTP 400で拒否します。停止時はパワー0を先に送信します。通信エラー時は停止入力へ戻し、復旧時に古い走行指令を再送しません。

ESP32はパワー指令が600ms以上届かない場合と、Wi-Fi端末がいなくなった場合に保存指令とモーター出力を停止します。HTTP処理に時間がかかる場合を含め、厳密な停止時間を保証するものではありません。操作端末は1台で使用してください。

IMUは現在のラジコンGUIで更新していないため、初期化も`enableImu = false`で省いています。画面には架空の計測値を表示しません。IMU単体の確認にはBNO055_test環境を使います。

ページの通信・停止入力の回帰テスト：`node --test test/radicon-page.test.cjs`

## PCで確認

`data/index.html` をブラウザーで開くと、ローカルプレビューになります。
ボタンを押したときの表示と、離したときに停止へ戻る動作を確認できます。
プレビュー中はESP32への通信は行いません。localhostで配信した場合も同様です。

## ESP32で使用

画面の編集先は `data/index.html` です。PlatformIOのビルド時にHTMLを
ファームウェアへ埋め込むため、変更後は通常のビルド・書き込みを行ってください。
ファイルシステムの別途書き込みは不要です。

ESP32のWi-Fiへ接続し、`http://192.168.100.1/` を開くと実際に通信します。
ローカルプレビューでは実機の通信やモーター動作は検証できません。

## ファイル構成

- `src/main.cpp`: 初期化、Wi-Fi AP、HTTP処理、指令と通信タイムアウトの管理、サーボ操作
- `lib/_others/settings.hpp`: Wi-FiのSSID・パスワード、サーボピン、タイムアウト
- `lib/Sg90Servo/`: サーボ制御ライブラリ
- `data/index.html`: 操作画面と通信ログ

`setup()`から`tryBegin()`で起動し、`loop()`から`update()`を呼びます。
通信が600ms途絶えた場合と、接続端末がなくなった場合の停止処理もmain.cppで管理します。

## SG90の接続と操作

通常の位置制御型SG90を1台接続できます（連続回転型は対象外）。

| SG90の線 | 接続先 |
| --- | --- |
| 信号（通常オレンジまたは黄） | ESP32 GPIO13 |
| 電源（通常赤） | サーボ用の安定化電源（製品の定格に合わせる。TowerPro SG90は4.8V） |
| GND（通常茶または黒） | 電源GNDおよびESP32 GND |

配線は電源を切って行い、サーボの電源をESP32の3.3V端子や信号GPIOから取らないでください。
外部電源を使う場合もGNDは共通にします。

書き込み後にESP32の画面を開き、「SG90 サーボ」のスライダーで指定します。
起動時には90°へ移動するので、初回はホーンに負荷をかけずに確認してください。
停止ボタンと通信タイムアウトは方向指令用です。サーボは最後の指定位置を保持し、
「90°へ戻す」ボタンで中央へ移動します。

- `lib/_others/settings.hpp`の`servoPin`で信号線のGPIOを変更できます。
- `lib/Sg90Servo/`でPWM制御を管理しています。外部Servoライブラリは使用せず、Arduino-ESP32 2.x標準のLEDC APIで50Hz・16bitのPWMを生成します。
- 指令値0〜180をパルス幅500〜2500µsへ変換します（従来のESP32Servoのデフォルトと同じ範囲）。現在のmain.cppでは角度を5〜175に制限しています。実際の可動角は個体によって異なります。
- 指定角度の表示は実測値ではありません。通信結果は通信ログに表示します。
- ローカルプレビューでのサーボ操作は通信を行いません。

仕様の参照: https://towerpro.com.tw/product/sg90-7/

## サーボPWMのチャンネル

Sg90ControllerはデフォルトでLEDCチャンネル14、RotationServoControllerは15を使います。この2チャンネルは同じタイマーを共有するため、50Hzのサーボ専用にしてください。他のPWM出力で使わないでください。複数インスタンスを使う場合は、コンストラクターで重複しないチャンネルを指定します。タイマーを共有するチャンネル同士も同じ周波数にそろえる必要があります。

Sg90Controllerのmove()は1回の呼び出しで加算する角度を受け取ります。set()は3度以下の変更も出力します。自動解除は従来同様、同じ角度でset()を呼び続け、3秒経過した時点で行います。呼び出しがない間は自動解除されません。stop()は自動解除が有効な場合にPWMを解除します。

RotationServoControllerのmove()は-1〜1（0が中立）を受け取り、stop()はPWMを解除します。PWM解除は信号の停止であり、サーボ電源の遮断ではありません。
